Подготовка к тесту O(n)

Шпаргалка по Chapter 1, циклам for/while/if-else, Big-O/Ω/Θ, пределам и классам эффективности. Потом тренажёр и пробный тест.

01Главный алгоритм решения «найди сложность»

  1. Последовательные блоки → складываем, потом берём больший: O(n) + O(n²) = O(n²). Если переменные разные — оставляем обе: O(n + m).
  2. Вложенные циклы → умножаем (если внутренний не зависит от внешнего): n · log n.
  3. Если внутренний зависит от внешнего (j ≤ i) → пишем сумму: 1+2+…+n = n(n+1)/2 → O(n²).
  4. if / else → берём худшую ветку (worst case). Само условие = O(1).
  5. Отбрасываем константы и младшие члены: n/2 → n, 3n²+5n → n², log₃n → log n.
  6. Смотрим, как меняется счётчик: +1/−1/+3 → n; ×2, /2, /3 → log n; p += i → √n.

03if-else и best/worst case

  • if(x>0) print(x), if-else с константной работой, цепочка else if, вложенные if → O(1).
  • if(x>0) O(n) работа else O(log n) → берём худшее → O(n).
  • if внутри цикла по n → O(n); if(i==j) внутри двух циклов → O(n²) (циклы доминируют, if не уменьшает число проверок).
  • while(i≤n){ if(cond) break; i++; } → best O(1), worst O(n).

Big-O может быть нестрогой (not tight): n = O(n²) — верно, но n ≠ Θ(n²). В книге Левитина k обозначают n₀, а «f = O(g)» пишут как «t(n) ∈ O(g(n))».

05Как доказывать O / Ω / Θ (найти c и k)

Шаблон O: каждое слагаемое оцениваем сверху старшей степенью (при n ≥ 1: n ≤ n², 1 ≤ n²), складываем коэффициенты → это c, k = 1.
Шаблон Ω: просто отбрасываем положительные младшие члены: 3n² + 2n ≥ 3n² → c = 3, k = 1.

Пример 1 (с лекции): 10n + 5 = O(n)

Нужно: 10n + 5 ≤ c·n  для всех n ≥ k
Берём c = 15:  10n + 5 ≤ 15n  ⇔  5 ≤ 5n  ⇔  n ≥ 1
Ответ: c = 15, k = 1

Другой вариант: 10n + 5 ≤ 11n ⇔ n ≥ 5 → c = 11, k = 5. Пар (c, k) бесконечно много, достаточно одной.

Пример 2: 3n² + 2n + 1 = O(n²)

При n ≥ 1:  2n ≤ 2n²,  1 ≤ n²
3n² + 2n + 1 ≤ 3n² + 2n² + n² = 6n²
Ответ: c = 6, k = 1

Пример 3: 100n + 5 = O(n²) (Levitin)

100n + 5 ≤ 100n + 5n = 105n ≤ 105n²   при n ≥ 1
Ответ: c = 105, k = 1

Пример 4: n² = Ω(n) (с лекции)

n² ≥ 1·n  при n ≥ 1   →   c = 1, k = 1

Пример 5: ½n(n−1) = Θ(n²) (Levitin)

Сверху: ½n² − ½n ≤ ½n²            при n ≥ 0   → c₂ = ½
Снизу:  ½n² − ½n ≥ ½n² − ½n·½n = ¼n²  при n ≥ 2   → c₁ = ¼
Ответ: c₁ = ¼, c₂ = ½, k = 2

Пример 6: 5n + 3 = Θ(n)

5n ≤ 5n + 3 ≤ 5n + 3n = 8n   при n ≥ 1   → c₁ = 5, c₂ = 8, k = 1

Как показать, что НЕ O: n³ ≠ O(n²)

Пусть n³ ≤ c·n² для всех n ≥ k  ⇒  n ≤ c для всех n ≥ k.
Но при n = max(k, c+1) это неверно. Противоречие.

06Сравнение через предел (Using limits)

            ⎧ 0      → f растёт медленнее g:  f ∈ O(g), f ∈ o(g)
lim f(n)/g(n) = ⎨ c > 0  → одинаковый порядок:   f ∈ Θ(g)
n→∞         ⎩ ∞      → f растёт быстрее g:    f ∈ Ω(g)
  • L'Hôpital: lim f/g = lim f′/g′. Пример: lim log₂n / √n = lim (1/(n ln2)) / (1/(2√n)) = lim 2/(ln2·√n) = 0 → log n растёт медленнее √n.
  • Stirling: n! ≈ √(2πn)·(n/e)ⁿ. Пример: lim n!/2ⁿ = ∞ → n! ∈ Ω(2ⁿ).
  • lim ½n(n−1)/n² = ½ → ½n(n−1) ∈ Θ(n²).
  • lim 2ⁿ/3ⁿ = lim (2/3)ⁿ = 0 → 2ⁿ и 3ⁿ — разные порядки!
  • logₐn = log_b n / log_b a → основание логарифма — просто константа, все log одного порядка.

Useful property

Если t₁ ∈ O(g₁) и t₂ ∈ O(g₂), то t₁ + t₂ ∈ O(max{g₁, g₂}). Алгоритм из двух последовательных частей определяется более медленной частью: сортировка O(n²) + проход O(n) = O(n²).

Ещё: свойство транзитивно (f ∈ O(g), g ∈ O(h) ⇒ f ∈ O(h)); f ∈ O(g) ⇔ g ∈ Ω(f).

08Space complexity

  • Несколько переменных (int a, b, c) → 3·4 = 12 байт → O(1).
  • Массив фиксированного размера 100 — хоть 1 элемент, хоть 100 → O(1) (не зависит от n).
  • Массив из n элементов: 4n + 8 байт → O(n).
  • Двумерный массив n × n / заполнение в двойном цикле → O(n²).
  • Range query в balanced BST: O(log n + k) времени (поиск a и b + k выведенных элементов).

09Теория Chapter 1 (определения)

  • Data Structure — способ хранения и организации данных, чтобы использовать их эффективно; логическая и физическая организация элементов данных с учётом их связей.
  • Algorithm — конечная последовательность точных вычислительных шагов для решения задачи.
  • Program = Algorithm + Data Structure. Решение задачи = способ организации данных + последовательность шагов.
  • Primitive DS — обрабатываются машинными инструкциями напрямую: integer, float, char, string constants, pointers.
    Non-primitive — группы однородных/разнородных данных: array, list, files, linked list, trees, graphs.
  • ADT (Abstract Data Type) — абстрактная структура данных + операции. Определяет что можно хранить и какие операции можно выполнять (пример: Employee — хранит нужные атрибуты; операции hire, fire, retire).
  • Abstraction — процесс разделения характеристик на важные и неважные и игнорирования неважных. Разница: ADT — это сущность, abstraction — процесс получения абстрактного взгляда.
  • Алгоритм меняет структуру данных двумя способами: меняет значение, хранимое в ней, или меняет саму структуру.

Analysis

  • Algorithm analysis — определение, сколько времени и памяти потребует алгоритм. Меры: running time (главная), memory usage, communication bandwidth.
  • Два подхода: Empirical — запрограммировать и запускать на разных входах; Theoretical — математически посчитать ресурсы.
  • Почему не секунды: время зависит от железа, загрузки и софта → используем asymptotic analysis (order of magnitude) — как растёт время при n → ∞.
  • Problem — задача, отображение входов в выходы (без ограничений на способ решения). Algorithm — метод решения; одна задача — много алгоритмов, один алгоритм решает одну задачу. Program — реализация алгоритма на языке программирования.
